Якщо дитина застрягла

Пошук вузлів

Вузли шукають англійською: правий клік по порожньому місці графа і почати друкувати назву. Підказки на сторінці записано так, як їх видно у Visual Scripting: On Trigger Enter 2D, Compare Tag, If. Змінні — це Get Variable/Set Variable типу Object (Variables на об'єкті; щоб дістати змінну гравця з графа іншого об'єкта, у порт об'єкта подаємо Collider), а в уроках 15–16 — Application. Усі написи в Canvas — TextMeshPro: шукайте вузли Text Mesh Pro UGUI.

Правило для рівнів: стрибок куба ≈ 4 клітинки. Сходинка, на яку стрибаєш, — щонайменше 5 клітинок завдовжки. Після сходинок — 8 клітинок рівної землі до наступної перешкоди. Більше двох шипів поспіль без батута не ставимо.

★Матеріали й варіанти

Уся графіка й звуки курсу вже лежать у проєкті. Для кожної речі є кілька варіантів, тож дитина може вибрати свій: інший колір куба, блоки, фон, звук стрибка. Графіка й звуки — Kenney (CC0), музика — Juhani Junkala (CC0), шрифт Lilita One (OFL).

Як поміняти: виділити об'єкт (або відкрити префаб) і перетягнути інший спрайт у поле Sprite компонента Sprite Renderer. Зі звуками так само: інший файл у змінну (jumpSound, deathSound…) або в Audio Source. Якщо змінити префаб, оновляться всі його копії на рівні.

1–3Біг, стрибок, звук

Уже зроблено разом (тег lesson-03): куб біжить, стрибає тільки з землі й грає звук стрибка. Камера стежить за кубом.

On Fixed UpdateOn UpdateIfзмінні speed, jumpVelocity, isGrounded, isAlivePlay One Shot

Ці групи є основою для всіх наступних уроків. Зміна isAlive у групі «Рух» уже вміє зупиняти біг, а isGrounded вирішує, чи можна стрибати.

4Шипи: смерть і перезапуск

Ціль: торкнувся шипа — рівень починається спочатку.

тригертег (Tag)IfLoad Scene

Сцена

  1. Створити порожній об'єкт Level — у ньому житимуть усі перешкоди.
  2. Перетягнути префаб Prefabs/Spike у Level. Позиції: x = 12, 22, 23, 34, 35; y = 0.5.
  3. Показати дитині: у шипа Box Collider 2D має галочку Is Trigger (крізь нього можна пройти, але гра дізнається про дотик), а Tag = Hazard («небезпека»).

Граф (PlayerRun), нова група «Смерть від шипів»

On Trigger Enter 2D→Compare Tag «Hazard»→If→ True →Set Variable isAlive = false→Load Scene «Level1»

Вихід Collider із події йде у вхід Compare Tag, а результат — в умову If. Для false — вузол Boolean без галочки.

Перевірка

  • Не натискати нічого: куб доїжджає до першого шипа, і рівень починається знову.
  • Зі стрибками можна пройти всі шипи.
Питання дитині: «Чому шип — тригер, а земля — ні?» (Об землю треба стукатися, а крізь шип — ні, нам треба лише знати, що доторкнулися.)

5Фініш і «ПЕРЕМОГА!»

Ціль: добіг до прапорця — куб зупиняється, на екрані великий напис «ПЕРЕМОГА!».

UI TextSet Activeзмінна-посилання на об'єкт

Сцена

  1. Префаб Prefabs/Finish поставити на x = 60 (його Tag = Finish).
  2. На Canvas: Canvas Scaler → Scale With Screen Size, 1920×1080.
  3. Canvas → UI → Legacy → Text, назва WinText: текст «ПЕРЕМОГА!», розмір 140, жовтий колір, додати компонент Outline. Вимкнути галочку біля назви об'єкта: напис схований.
  4. У Variables гравця додати winText (тип GameObject) і перетягнути туди WinText.

Граф, група «Фініш»

On Trigger Enter 2D→Compare Tag «Finish»→If→Set Variable speed = 0→Set Active (winText, ✓)
Чому speed = 0, а не isAlive = false? Група «Рух» щокадру ставить швидкість = speed, тож speed = 0 зупиняє куб. А isAlive = false просто перестане оновлювати швидкість, і куб поїде далі.

6Будуємо рівень

Ціль: власний рівень зі сходинками й шипами. Урок без графів: тільки сцена й тестування.

префабTiled-спрайтгра-тестування

Префаб Block

  1. Новий об'єкт Block: Sprite Renderer зі спрайтом block_blue (або будь-який block_*, bricks_grey), Draw Mode = Tiled, Size 1×1.
  2. Box Collider 2D з галочкою Auto Tiling: колайдер сам розтягується разом зі спрайтом.
  3. Перетягнути в Prefabs. Довгий блок — змінити Size → Width, вищий — Height.
  4. Можна зробити кілька префабів різних кольорів, і дитина сама вибере, які їй подобаються.
Не беріть для високих блоків terrain_*_block_top: у режимі Tiled трава повторюється в кожному рядку, і блок висотою 2 виглядає як два шари один на одному. Готова точка lesson-06 ще використовує terrain_purple_block_top — дитина на уроці вибрала block_blue.
Ставте все по сітці. Блок 1×1 стоїть рівно, коли y = 0.5, 1.5, 2.5…, шипи — на y = 0.5. Найпростіше — вписати точні числа в Transform → Position в Inspector.

7Краса: обертання, вибух, звуки

Ціль: куб крутиться в стрибку; від шипа розлітається на квадратики зі звуком, а на фініші грає «чарівний» звук.

Transform RotateTime.deltaTimeParticle SystemWait For SecondsAnd

Сцена й змінні

  1. У Player додати дочірній Particle System Boom:
    • Looping вимкнено, Play On Awake вимкнено.
    • Start Speed 4–10, Start Size 0.2–0.4, колір — випадковий між синім і жовтим, Gravity Modifier 1.5, Simulation Space = World.
    • Emission: Rate 0, один Burst на 40 частинок. Shape = Circle.
    • Renderer: матеріал Sprite-Unlit-Default (виходять квадратики, як у Geometry Dash), Order in Layer 20.
  2. Змінні гравця:
    • visual (GameObject Visual);
    • spinSpeed = −360;
    • boom (Boom);
    • deathSound = sfx_hurt;
    • winSound = sfx_magic.
    • Звуки можна вибрати інші: retro_death/soft_death, retro_win/soft_win (див. «Матеріали»). Колір частинок теж на смак.

Нова група «Крутимось у стрибку»

On Update→If isGroundedTrue →Set Local Euler Angles (visual) = 0,0,0
False →Rotate (visual), Z = spinSpeed × Get Delta Time

Смерть стає красивою

У ланцюжок смерті після Set isAlive = false вставити кроки:

Set Simulated = false→Set Active (visual, ✗)→Play (boom)→Play One Shot (deathSound)→Wait For Seconds 1→Load Scene
  • У події On Trigger Enter 2D поставити галочку Coroutine, інакше Wait For Seconds не працюватиме.
  • В умову додати And з isAlive: смерть не спрацює двічі, якщо куб зачепить два шипи.

У «Фініш» після Set Active додати Play One Shot (winSound).

Якщо не встигаєте, урок легко ділиться навпіл: спершу обертання, а наступного разу вибух і звуки.

8Батут

Ціль: пружина підкидає куб дуже високо — на стіну, через яму з шипами.

новий тег PadSet Linear Velocity Y

Ассети

Уже в проєкті: spring.png, spring_out.png, sfx_jump-high.ogg.

Сцена

  1. Префаб Pad:
    • спрайт spring, ширина ≈ 1 клітинка;
    • Box Collider 2D з Is Trigger;
    • новий Tag Pad.
  2. Рівень:
    • батут на x = 124, одразу за ним стіна-блок 127–133 висотою 3;
    • батут на x = 145, за ним шипи на 147, 148, 149;
    • фініш перенести на 162.
  3. Змінні: padVelocity = 28, padSound = sfx_jump-high.

Граф, група «Батут»

On Trigger Enter 2D→Compare Tag «Pad»→If→Set Linear Velocity Y = padVelocity→Set isGrounded = false→Play One Shot (padSound)
Експеримент: поміняти padVelocity і подивитися, що буде. З 24 куб у наших тестах приземлявся просто на шипи, тому в готовій точці стоїть 28.

9Кожному об'єкту свій граф

Уже зроблено разом (20.10): код, що стосується шипів, батута й фінішу, переїхав з гравця на самі об'єкти. Тепер кожен об'єкт сам знає, що він робить із гравцем.

Script Machine на об'єктіTag PlayerCustom Eventзмінні на об'єкті

Як це влаштовано тепер

Об'єктГрафЩо робить
spikes, wall (префаби)HazardГравець торкнувся, і об'єкт каже йому «Смерть»
springPadПідкидає гравця на power, грає sound, міняє спрайт на pressed

Custom Event «Смерть»→isAlive = false→вибух, звук→Wait For Seconds 2→Load Scene

Шаблон для всіх нових об'єктів однаковий: On Trigger Enter 2D → Compare Tag «Player» → If → дія. Вихід Collider — це гравець, якого торкнулися. Від нього беремо його змінні (Get/Set Variable типу Object, порт об'єкта = Collider) або надсилаємо йому подію.

Дві дороги, і обидві правильні. Якщо треба просто змінити число гравця (батут, зірка), об'єкт змінює його сам через Collider. Якщо гравець має щось зробити (померти, стати кораблем), об'єкт надсилає Custom Event, а що саме робити, вирішує граф гравця.
Custom Event, після якого йде Wait For Seconds, має стояти з галочкою Coroutine. Без неї очікування мовчки не працює, і помилки в консолі немає.

Чим це краще: нова перешкода — це будь-який спрайт + тригер + граф Hazard. У гравця нічого міняти не треба.

10Зірки й лічильник

Ціль: зірки можна збирати. Взяв зірку — вона зникає з дзвоном, а число в кутку екрана збільшується.

префаб зі своїм графомOn Start + FindAddTo StringSet text (TextMeshPro)Destroy

Ассети

Уже в проєкті: star.png, sfx_coin.ogg. Замість зірки можна збирати кристали gem_yellow/gem_red (звук sfx_gem).

Сцена

  1. Гравцю — нова змінна coins (Integer, 0). Лічильник живе на гравці, а не на зірці, бо зірки зникають.
  2. У Canvas — текст UI → Text - TextMeshPro з назвою starText і текстом «0», угорі екрана. Поруч — Image зі спрайтом зірки.
  3. Префаб star:
    • спрайт star;
    • Circle Collider 2D з Is Trigger, радіус 0.35;
    • Variables: starText (тип Text Mesh Pro UGUI), starSound = sfx_coin;
    • Script Machine з новим графом Scripts/Star.
  4. Зірки ставимо там, де куб пролітає: над шипами, на сходинці, на дузі батута.

Граф Star, група «Знайти напис»

Префаб не може тримати посилання на об'єкт зі сцени, тому кожна зірка на старті сама знаходить напис за назвою.

On Start→Game Object Find «starText»→Set Variable starText (This)

Граф Star, група «Зірка»

On Trigger Enter 2D→Compare Tag «Player»→If→Play One Shot (Collider, starSound)→Set coins (гравець) = coins + 1→Set text (starText) = coins → To String→Destroy (This)
  • Звук граємо на гравці: Audio Source: Play One Shot, ціль — Collider. Якщо грати на самій зірці, звук обірветься, бо вона одразу зникає.
  • Set Variable coins бере гравця з правого виходу Play One Shot, як на батуті isGrounded бере його з Set Linear Velocity Y. Так не треба тягнути ще одну довгу лінію від Collider.
  • Get Variable coins стоїть під ланцюжком і бере гравця прямо з Collider.
  • Get Variable starText ставимо над Set text, а To String — під ним: тоді лінії не перехрещуються.
  • Destroy — останнім, бо після нього граф зірки вже не працює.
Дві пастки, на які ми вже наступили:
  • Число не можна подати прямо в текст: помилка Cannot convert from 'System.Single' to 'System.String'. Між числом і Set text ставимо To String.
  • Текст у Canvas — це Text Mesh Pro UGUI. Вузол Text Mesh: Set Text і тип Text Mesh Pro (без UGUI) — для тексту в самій сцені, з ними буде Missing target object або There is no 'TextMesh' attached. У пошуку вузлів набираємо Text Mesh Pro UGUI → Set text.

11Меню

Ціль: гра починається з меню. Натискаєш «ГРАТИ» — запускається рівень. Після перемоги через 3 секунди — знову меню.

нова сценаButtonOn Button ClickBuild SettingsCoroutine

Сцена Menu

  1. File → New Scene, зберегти як Scenes/Menu.
  2. Камера: Orthographic, Size 6. Дочірній Background з фоном пагорбів, як у рівні.
  3. UI:
    • Canvas (Scale With Screen Size 1920×1080) і EventSystem (з Input System UI Input Module);
    • заголовок «GEO GAME» (Text - TextMeshPro) — жовтий з обводкою;
    • кнопка PlayButton «ГРАТИ».
  4. На кнопку — Script Machine з новим графом Scripts/PlayButton. Граф живе на самій кнопці, як і всі наші графи.
  5. File → Build Profiles / Build Settings: сцени Menu (перша) і Level1.
On Button Click→Load Scene «Level1»

Повернення в меню: граф Finish

Відкриваємо граф Finish на фініші. В On Trigger Enter 2D ставимо галочку Coroutine, а в кінець ланцюжка дописуємо:

… winText ✓→Wait For Seconds 3→Load Scene «Menu»
Щоб грати з меню, у редакторі відкривайте сцену Menu перед натисканням Play.

12Портал гравітації

Ціль: пролетів через фіолетовий портал — куб падає на стелю й біжить догори дриґом. Другий портал повертає все назад.

Custom Event гравцюзмінна з назвою подіїмноження на −1Gravity Scale

Ассети

Уже в проєкті: portal_purple.png, sfx_magic.ogg.

Сцена

  1. Префаб GravityPortal:
    • спрайт portal_purple;
    • Box Collider 2D 1×3 з Is Trigger;
    • Variables: message (String) = «Гравітація», sound = sfx_magic;
    • Script Machine з новим графом Scripts/Portal.
  2. Продовжуємо рівень за фінішем (фініш переносимо далі):
    • стеля — довгий блок на висоті y = 7, приблизно 40 клітинок;
    • перший портал біля землі (y = 1.5) на початку стелі;
    • другий портал біля стелі (y = 5.5) в її кінці;
    • на стелі — 2–3 шипи, повернуті на 180° (y = 6.5). Це звичайний префаб spikes, тож вони вже вбивають.

Граф Portal (на порталі)

Портал нічого не знає про гравітацію. Він лише каже гравцю слово зі своєї змінної message. Тому той самий граф знадобиться ще для двох порталів в уроці 14.

On Trigger Enter 2D→Compare Tag «Player»→If→Play One Shot (Collider, sound)→Trigger Custom Event (кому: гравець з виходу Play One Shot, назва: Get Variable message)

Граф PlayerRun, нова група «Гравітація»

Custom Event «Гравітація»→Set Gravity Scale = Gravity Scale × −1→Set jumpVelocity = jumpVelocity × −1
Чарівне в цьому уроці — множення на −1: «вниз» стає «вгору», а стрибок теж розвертається. Нехай дитина вгадає, що буде, якщо забути розвернути jumpVelocity.
Назва в Custom Event гравця має збігатися з message на порталі літера в літеру, разом з великою літерою. Інакше портал «кричить», а гравець не чує, і помилки немає.

13Рухома пила

Ціль: пила крутиться й їздить туди-сюди. Нових вузлів немає — тільки вікно Animation і готовий граф Hazard.

Animationключові кадриAnimatorзнову граф Hazard

Ассети

Уже в проєкті: saw.png.

Кроки

  1. Порожній об'єкт MovingSaw, у ньому дочірній Saw:
    • спрайт saw;
    • Circle Collider 2D з Is Trigger;
    • Script Machine з графом Hazard — той самий, що на шипах. Пила вже вбиває!
  2. Виділити MovingSaw, Window → Animation → Animation → Create → Animations/SawMove.
  3. Натиснути червону кнопку запису:
    • кадр 0:00 — Saw x = 0, обертання Z = 0;
    • кадр 2:00 — x = 2;
    • кадр 4:00 — x = 0, обертання Z = −1440.
  4. Перевірити, що в кліпі стоїть Loop Time. Зробити з MovingSaw префаб і поставити 2 пили на рівні, між ними ≥ 16 клітинок.
Тут добре видно, навіщо був урок 9: раніше пилу треба було б додавати в граф гравця, а тепер вона приносить свою поведінку з собою.
Пила має їздити повільно (2 клітинки за 4 секунди). Ми перевіряли швидшу пилу: вона їде в той самий бік, що й куб, і він приземляється просто на неї.

14Корабель

Ціль: помаранчевий портал перетворює куб на корабель. Тримаєш кнопку — летиш угору, відпускаєш — падаєш. Зелений портал повертає куб.

«тримати», а не «натиснути»Add Forceтой самий граф PortalCustom Event

Ассети

Уже в проєкті: ship_blue.png, portal_orange.png, portal_green.png.

Сцена й змінні

  1. У Player — дочірній Ship зі спрайтом ship_blue, повернутий на −90° (носом управо). Вимкнений.
  2. Змінні гравця: ship (Ship), isShip = false, shipPower = 45.
  3. Два нові портали — копії GravityPortal з іншим спрайтом і іншим message:
    • ShipPortal: portal_orange, message = «Корабель»;
    • CubePortal: portal_green, message = «Куб», розтягнутий на всю висоту.
    Граф у них той самий — Portal. Нічого нового в ньому робити не треба.
  4. Рівень: портал корабля біля землі, далі стеля на висоті 8 і стовпи-блоки по черзі знизу (висота 4) і згори (від 4.5 до 8) кожні 8 клітинок, наприкінці — портал куба, потім фініш.

Граф PlayerRun, групи «Стати кораблем» і «Стати кубом»

Custom Event «Корабель»→isShip = true→Gravity Scale = 2→Set Active visual ✗→Set Active ship ✓
Custom Event «Куб»→isShip = false→Gravity Scale = 7→Set Active visual ✓→Set Active ship ✗

Граф PlayerRun, група «Корабель летить»

On Fixed Update→If isShip→If (Space або ліва кнопка затиснута)→Add Force (Vector2 0, shipPower)

Умову «затиснута» можна скопіювати з групи «Стрибок зі звуком»: там те саме Is Pressed. Політ лишається в гравці, бо це його власне вміння, а не дія порталу.

Стовпи — звичайні блоки: в них не помираєш, просто впираєшся. Для 8 років так менше сліз. Хто хоче складніше — поставте шипи на краях стовпів.

15Спроби й прогрес

Ціль: угорі видно «Спроба 5» і смужку, що заповнюється дорогою до фінішу.

змінна ApplicationOn StartString ConcatділенняImage Fill Amount

Ассети

Уже в проєкті: UI/bar_track.png, UI/bar_fill.png.

Спроби: граф на самому написі

  1. Текст AttemptText (Text - TextMeshPro) у правому верхньому куті.
  2. На нього — Script Machine з графом Scripts/Attempts.

Звичайні змінні обнуляються, коли рівень перезапускається. Змінні Application живуть, поки працює гра, — саме те для лічильника спроб.

On Start→Set Variable (Application) attempts = attempts + 1→Set text (This) = String Concat «Спроба » + attempts

Текст беремо з самого об'єкта: у Text Mesh Pro UGUI: Set text порт цілі лишаємо This.

У Get Variable (Application) у порт Fallback треба підключити окремий вузол Integer 0. Вписане прямо в порт значення Visual Scripting ігнорує, і гра падає з помилкою «Missing input value for 'fallback'».

Прогрес: граф на смужці

  1. UI Image ProgressBar (bar_track, Sliced, 700×44, угорі по центру). У ньому дочірній Fill: bar_fill, Image Type = Filled, Horizontal, Fill Amount 0.
  2. На Fill:
    • Variables: player (Transform гравця), finish (Transform фінішу);
    • Script Machine з графом Scripts/Progress.
On Update→Set Fill Amount (This) = x гравця ÷ x фінішу

16Скіни й музика

Ціль: у меню вибираєш колір куба (синій, зелений, рожевий), і в грі куб саме такий. У меню й у рівні грає музика.

Application між сценамиHas VariableSet Spriteодин граф на три кнопкиAudio Source Loop

Ассети

Уже в проєкті: 24 скіни в Sprites/Skins, 12 облич, музика menu і level1–level3. У прикладі три кнопки (синій, зелений, рожевий), а дитина може вибрати будь-які кольори й форми.

Меню: кнопки скінів

  1. Три кнопки Skin1–Skin3, картинка кожної — спрайт скіна.
  2. На кожній кнопці:
    • Variables: skin (Sprite), clickSound = sfx_coin;
    • Audio Source (Play On Awake вимкнено);
    • Script Machine з одним спільним графом Scripts/SkinButton.

Як і з порталами: граф один, а кнопки відрізняються лише своєю змінною skin.

On Button Click→Set Variable (Application) skin = Get Variable (Object) skin→Play One Shot (clickSound)

Рівень: граф на Visual

Скін міняє той, хто його носить, — дочірній об'єкт гравця Visual (на ньому Sprite Renderer куба). Даємо йому Script Machine з графом Scripts/Skin:

On Start→If (Has Variable Application «skin»)→Set Sprite (This) = Get Variable (Application) skin

Перевірка Has Variable потрібна, щоб гра не ламалася, коли запускаєш одразу рівень, без меню.

Музика

На Main Camera в обох сценах — Audio Source: кліп menu або level1, Loop ✓, Play On Awake ✓, Volume 0.4. Графи не потрібні. Музика — Juhani Junkala, ліцензія CC0.

17Свій рівень

Ціль: дитина сама будує рівень із усього, що вміє, і дає пограти родині.

  1. Зберегти копію сцени: Level1 → Ctrl+D → Level2, прибрати в ній усе з Level.
  2. Спершу намалювати рівень на папері: де батут, де портал, де корабель.
  3. Будувати з префабів по шматочку й одразу проходити. Кожен префаб приносить свій граф, тож шипи, зірки й портали працюють одразу. Правило 4 / 5 / 8 клітинок допомагає.
  4. Додати сцену в Build Settings, а в меню — другу кнопку з Load Scene «Level2» (той самий граф, що в PlayButton, тільки інша назва сцени). Фініш другого рівня теж веде в меню — граф Finish уже вміє.
  5. Тест на друзях: дати пограти, мовчки дивитися, де вони гинуть, і полагодити найнечесніше місце.
Ідеї на потім: свій об'єкт зі свого графа — лава (Hazard), кристал на 5 очок (як зірка, але coins + 5), швидкісний портал (Portal з message «Швидко» і група в гравці, що ставить speed = 12).
